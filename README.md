# SupportPilot - Milestone 1

The screen-sharing explanation is in [the main-files presentation guide](docs/SupportPilot_Main_Files_Presentation.pdf).

Flask ticket intake, TF-IDF and logistic regression classification, PDF severity
rules, priority, confidence, SQLite storage, and manual ticket closure.

## Setup

Install Python 3.12 and open PowerShell in this folder.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe app.py
```

Open http://127.0.0.1:5000/. The app stores records in tickets.db and loads
models/ticket_classifier.pkl. Only load model artifacts shipped with this project
or generated by its training script.

## Kaggle dataset

[IT Service Ticket Classification Dataset](https://www.kaggle.com/datasets/adisongoh/it-service-ticket-classification-dataset)
by Adison Goh, CC0 Public Domain. The downloaded CSV contains 47,837 already
processed ticket documents and eight original category labels. See data/README.md
for counts, source details, checksum, and transformation steps.

Training uses 38,269 rows, with 9,568 separate rows for evaluation.
Measured category accuracy is 8,209/9,568 (85.8%), below the milestone's 90% target.
These categories replace the earlier synthetic six-category model.
The source has no severity ground truth. Severity follows the PDF keyword rules,
and its accuracy cannot be evaluated against this Kaggle file.

## Reproduce training and evaluation

```powershell
.\.venv\Scripts\python.exe prepare_data.py
.\.venv\Scripts\python.exe train_model.py
.\.venv\Scripts\python.exe -m pytest -q
```

prepare_data.py uses the supplied CSV under data/raw. It deduplicates normalized
text before a stratified 80/20 split with random_state=42. TF-IDF is fitted only
on training text. Evaluation checks train/test overlap and prints a classification
report and measured timings. Restart the server after retraining.

## Demo and API

Submit an employee name, email, department, title and description through the
form. Business impact is optional. Category and confidence come from the model.
Severity and priority follow the milestone PDF code. With severity-only priority,
Critical maps to P1, High to P2, Medium to P3 and Low to P4. With High business
impact, High severity maps to P1. The PDF's supplied business-impact formula maps
Critical with Standard impact to P4.

POST /ticket accepts a full record or a minimal JSON object containing description.
Minimal requests return ticket, category, severity, priority and status.
Full requests return 201 and a saved record. GET /api/tickets lists the latest
50 tickets; GET /api/tickets/{id} retrieves one. After solving an issue, open its
detail page and click **Mark as resolved & close**.

## Files

app.py handles Flask, validation and API routes. classifier.py contains
preprocessing, training, prediction, severity and priority. database.py manages
SQLite. train_model.py saves the model and runs evaluation. evaluation.py scores
the held-out set. templates/ and static/ contain the Bootstrap UI.

The demo allows unauthenticated access to tickets. Use sample contact details.
Confidence is an uncalibrated model probability. Kaggle labels can be broad and
the PDF severity keywords miss some expressions. See DEMO_GUIDE.md for the
screen-sharing explanation.
